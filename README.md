# Frontend Project Playbook

Правила и скиллы для команды, которая строит фронтенд на **React, Vite, TypeScript и Feature-Sliced Design**. Профиль использует Effector для состояния, Atomic Router для маршрутов, React Hook Form и Zod для форм, CSS Modules для стилей и Yarn для команд. Это набор инструкций для работы с кодом; приложение и зависимости он не устанавливает.

## Как подключить

1. Откройте [AGENTS.md](AGENTS.md) и проверьте, что этот стек и правила подходят вашему проекту.
2. Для **Codex** перенесите `AGENTS.md` и нужные папки из `.agents/skills/` в те же пути относительно корня вашего проекта. Если `AGENTS.md` уже есть, объедините правила вручную и оставьте в таблице только подключённые скиллы.
3. Для **Cursor** перенесите нужные файлы из [`.cursor/rules/`](.cursor/rules/). Правило `frontend.mdc` действует на весь проект и фиксирует стек; подключайте его, если команда уже приняла этот стек.

## Что входит

| Скилл Codex | Когда применять |
| --- | --- |
| [fsd-api](.agents/skills/fsd-api/SKILL.md) | Сервисы данных, JSON-моки и переход на реальный API |
| [fsd-effector](.agents/skills/fsd-effector/SKILL.md) | Модели, события, эффекты и состояния асинхронных операций |
| [fsd-forms](.agents/skills/fsd-forms/SKILL.md) | Поля, Zod-валидация и связь формы с моделью |
| [fsd-routing](.agents/skills/fsd-routing/SKILL.md) | Маршруты страниц, вложенные layout и единый реестр |
| [fsd-ui](.agents/skills/fsd-ui/SKILL.md) | CSS Modules, токены, общий UI и доступность |

Правила Cursor дополнительно выделяют общие соглашения по стеку, FSD, именованию и импортам. Пути к файлам и имена обёрток в примерах сверяйте со своим проектом. Если у вас другой стек, берите отдельные подходы и адаптируйте их к своим инструментам.
