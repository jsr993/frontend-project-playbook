# Формы в ВКС

## Сначала проверь доступные компоненты

- Открой `src/shared/form/index.ts` и реализацию нужных утилит. Потребители импортируют их только из `@/shared/form`, без доступа к внутренним путям.
- Если задача требует отсутствующего поля, реализуй только нужный компонент и явно экспортируй его из `shared/form/index.ts`. Не создавай сразу весь набор полей.
- Интеграцию RHF/Zod держи в `shared/form`; независимые от формы базовые UI-контролы — в `shared/ui`.

## Сборка формы

1. Определи Zod schema рядом со сценарием, обычно в `lib.ts`, и задай `defaultValues`.
2. Выводи типы из schema. Если есть преобразования, различай `z.input` для исходных значений и `z.output` для результата валидации.
3. Вызови `useAppForm({ schema, defaultValues })` и оберни форму в `FormProvider {...form}`.
4. Используй доступные компоненты полей. Не передавай вручную `control`, `register` и `errors`, если их задачу уже решает form-компонент.
5. Передавай проверенные значения в Effector-событие: `form.handleSubmit((values) => formSubmitted(values))`. API из формы напрямую не вызывай.
6. При открытии экрана или модального окна сбрасывай форму через `reset(defaultValues)`. Не сбрасывай пользовательский ввод при каждом рендере.

`useAppForm` уже подключает `standardSchemaResolver` из `@hookform/resolvers/standard-schema`. Переиспользуй эту обёртку, не добавляй второй resolver в компоненты формы.

## Поведение полей

- `name` — типизированный путь поля RHF. Ошибки и их тексты задаёт Zod schema, а не HTML5 validation; у `<form>` всегда ставь `noValidate`.
- RHF владеет значениями, dirty/touched и клиентской валидацией. Effector владеет состоянием сценария, submit, pending, серверными ошибками и options из API; не дублируй значения полей в сторах.
- Для условных полей используй `dependencies` и `visible`/`disabled` как boolean или функцию. Подписывайся через `useWatch` только на объявленные зависимости.
- `visible={false}` убирает поле из UI, сохраняя его значение. Не очищай скрытое значение без требования сценария.
- В существующей утилите значения зависимостей собираются по строкам `FieldPath`. Не предполагай вложенную форму объекта для путей с точками без проверки реализации.
- При реализации `FormInput` поддержи нужные задаче `type` (`text`, `email`, `password`) и `startElement`; для password предусмотрен встроенный переключатель видимости.

## Проверка

Проверь соответствие импортов реальным экспортам, ошибки валидации, передаваемые submit-значения, reset и поведение скрываемых полей. После изменения кода выполни `yarn build`.
