# Роутинг на Atomic Router

## Рекомендуемая схема

Перед изменением найди точки подключения в целевом проекте. Ниже схема из исходного профиля; имена файлов адаптируй к проекту:

- `src/pages/<page>/model.ts` — экземпляр маршрута через `createRoute`.
- `src/pages/<page>/index.ts` — публичный экспорт маршрута и компонента страницы.
- `src/pages/index.ts` — композиционный реестр `routes` с полями `path`, `route`, `view` и при необходимости дочерними `routes`; отдельно экспортируются `notFoundRoute` и `NotFoundPage`.
- `src/app/router/route-config.ts` — тип `RouteConfig`.
- `src/app/router/routes-history.ts` — преобразование дерева в маршруты history router, настройка `notFoundRoute` и browser history.
- `src/app/router/routes-view.tsx` — преобразование того же дерева в представления и родительские layout-компоненты; fallback — `NotFoundPage`.
- `src/app/App.tsx` — подключение `RouterProvider` и `RoutesView`.

Если проект уже хранит маршруты в другом месте, переиспользуй его реестр. Не создавай параллельные объявления и второй экземпляр маршрута для той же страницы.

## Добавление и изменение маршрута

1. Переиспользуй существующий экземпляр маршрута или создай его в модели страницы по принятому шаблону.
2. Экспортируй маршрут и компонент через публичный API страницы и подключи их в `src/pages/index.ts`.
3. Задай `path`, `route`, `view` в общем реестре. При вложенности учитывай, что дочерний путь соединяется с родительским, а layout получает содержимое через `children`.
4. Сохраняй один источник конфигурации для history и представлений. Не добавляй ручную регистрацию того же пути в другом месте.
5. Если навигация запускает бизнес-логику, свяжи её с Effector-моделью в рамках существующих зависимостей FSD.

Реестр `src/pages/index.ts` собирает публичные API страниц; это существующая композиционная точка, а не разрешение импортировать одну страницу из другой.

## Границы и проверка

- Добавляй и обновляй нужные задаче маршруты самостоятельно. Для обычного изменения в принятой схеме отдельное согласование не требуется.
- Не меняй архитектуру роутинга и не вводи другой роутер без явного запроса. Если схема отсутствует или задача требует неразрешённого архитектурного решения, уточни его.
- Проверь идентичность экземпляра маршрута в модели и регистрации, итоговый путь, вложенные layout и fallback для неизвестного URL. После изменения кода выполни `yarn build`.
