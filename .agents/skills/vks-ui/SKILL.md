# UI и стили в ВКС

## Размещение и API компонентов

- Перед созданием компонента проверь существующие реализации и дизайн-токены в `src/app/styles/global.css`.
- Доменный UI оставляй в своём слайсе. В `shared/ui` размещай независимые от предметной области компоненты без API-запросов, бизнес-моделей и импортов верхних слоёв.
- Передавай бизнес-данные и действия через типизированные props и callbacks; локальное UI-состояние допустимо.
- Создавай только нужные задаче компоненты и варианты. Выделяй повторяющиеся паттерны или явно запрошенные компоненты UI-kit, не создавай библиотеку заранее.
- Для общего компонента используй структуру `shared/ui/button/Button.tsx` и соседний `button.module.css`.
- Публичные компоненты и типы явно экспортируй из `shared/ui/index.ts`; helpers оставляй приватными. Потребители используют `@/shared/ui/`, внутри сегмента — относительные импорты.
- Сохраняй необходимые нативные props и обработчики, задавай разумные значения по умолчанию. Для вариантов предпочитай `variant`/`size` вместо конфликтующих boolean-флагов; поддерживай `className`, когда это нужно потребителю.
- RHF/Zod-интеграция относится к `shared/form`, а не к базовым UI-контролам.

## Стили

- Используй соседний `*.module.css` и `className`. Сохраняй установленную систему стилей; не добавляй UI-библиотеку ради оформления и не мигрируй компоненты без запроса.
- Переиспользуй общие CSS-переменные для цветов, отступов, типографики, радиусов и теней. Новые общие токены добавляй по необходимости.
- В глобальном CSS оставляй только reset, шрифты, токены, темы и базовые стили документа. Стили конкретных компонентов держи локально.
- Статические стили и варианты задавай классами. Inline styles используй только для вычисляемых во время выполнения значений, предпочтительно через CSS-переменные.
- Селекторы должны быть локальными и неглубокими. Избегай ID, `!important` и зависимости от внутренней разметки другого компонента.

## Поведение и проверка

- Сохраняй семантический HTML и работу с клавиатуры. CSS Modules отвечают за оформление; доступное поведение контролов реализуй отдельно.
- Предусматривай адаптивность, видимый keyboard focus и применимые состояния hover, disabled и error.
- Проверь компонент в нужных состояниях и размерах экрана, публичные экспорты и отсутствие бизнес-зависимостей в общем UI. После изменения кода выполни `yarn build`; если визуальную проверку не выполнял, укажи это в результате.
